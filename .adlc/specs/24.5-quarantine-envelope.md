# §24.5 — The quarantine resource envelope

**Ticket.** T34. **Status.** Working spec for the BUILD slice §24.9 deferred. §24.5 already carries
the design as a RECOMMENDATION; this spec settles the mechanism and names every rail. The landing PR
is Myk's merge: it adds a budget surface on a capability boundary.

**One sentence.** A quarantine pool runs its untrusted renders on its OWN worker envelope — slots,
wall clock, and memory — declared by the operator on the PARENT store as data, so a stranger's app can
burn its whole envelope without the primary's doors slowing down or losing a slot.

## 24.5a Why this is not a performance nicety

Under container-scoped trust an operator delegates almost everything to a child container. A child may
admit deltas its parent does not trust. Two powers do not delegate, and the operator keeps both:

- **Erasure reach.** The operator can still forget, through the glass, unconditionally (§24.8, built).
- **The bill.** The operator can still cap what the child spends on the operator's host. That is this
  section.

Take the second power away and delegated admission becomes an unbounded bill on someone else's say-so.
That is why the envelope is authored on the PARENT and read from the parent's ground: a child that may
admit what its parent distrusts must never be able to admit a delta that raises its own ceiling.

## 24.5b The honesty flags stay open — BOTH of them

§24.5 states it and this build does not outgrow it. A `worker_threads` Worker bounds HANG, CRASH, and
MEMORY. It does **not** bound ambient authority: a worker can still reach `node:fs` or open a socket.
Until the full no-fs/no-net ocap layer ships (SES-in-worker or isolated-vm — §23.9's named further
work, its own ticket and a dependency conversation), a quarantine that admits rung (d) effectful code
bounds resource exhaustion and does **not** bound reach. This slice builds the resource half only. The
quarantine does not yet safely run a stranger's effectful app.

**And the second flag, which the ticket did not name.** A stranger's bundle has no path INTO a pool
today. `publishRenderer` admits the operator's voice only, and a pool is opened with the parent's
operator seed, so every renderer a pool can execute is one the operator published. Foreign law
federates in as data and stays inert (§8/§12/§15). So this slice builds the bill for a workload whose
ADMISSION path is still §24.3/§24.4's promotion — the envelope is ready before the door it will meter
is open. Stated here rather than implied, because the one-sentence promise reads like the stranger can
already get in. They cannot, and this section does not change that.

## 24.5c The model

1. **The envelope is DATA, following `loam:budget`.** One operator-authored declaration at
   `loam:envelope`, re-resolved from the live deltas on every render. Raising a pool's slot count is a
   delta, not a restart. Malformed declarations are refused at the append door, so the door and the
   reader can never disagree.
2. **The declaration lives on the PARENT and is read from the parent.** The pool's gateway holds a
   resolver closed over the parent's reactor. A delta appended inside the pool at `loam:envelope`
   changes nothing about the pool's envelope. This is 24.5a made mechanical.
3. **Three dimensions.** `maxConcurrentRenders` (slots), `renderTimeoutMs` (wall clock),
   `maxMemoryMb` (per-worker old-generation ceiling). The shape is extensible by ADDITION: an
   unrecognized dimension is a newer store's limit, tolerated and ignored.
4. **A pool with no declaration is BOUNDED, not unmetered.** This is the one place the shape
   deliberately diverges from `budget.ts`, where an author with no declaration is unmetered. An
   unmetered author is the operator's own trusted grantee. An unmetered quarantine is exactly the
   unbounded bill this section exists to close. The built-in default is
   `{ maxConcurrentRenders: 4, renderTimeoutMs: 500, maxMemoryMb: 128 }`.
5. **Resolution is per dimension.** A declaration naming the pool's container entity wins; else a
   declaration for the wildcard subject `*`; else the built-in default. Each dimension resolves on its
   own, so a wildcard raise and a per-pool tightening compose — a per-pool declaration naming only the
   clock must not silently reset the wildcard's slots to the built-in default. This is where the shape
   departs from `readBudgetPolicy`, which picks a latest declaration per subject WHOLESALE.
5b. **An anonymous pool has a HANDLE, and a handle is not a subject.** `openQuarantine` opens a pool
   with no container entity. It resolves the wildcard-or-default envelope, and it is reported under a
   stable synthetic handle (`anonymous#1`, `anonymous#2`, … per parent) so an operator can tell two of
   them apart. The report carries the handle and the declared `container` as SEPARATE fields, and only
   the latter is a valid subject: a handle printed where a subject goes would invite a declaration the
   door accepts and the resolver ignores — a success returned over a no-op — and would share a
   namespace with real container names, since a container may lawfully be called `anonymous#1`.
5c. **A pool may open a pool, and the report and the ceiling both follow it down.** `envelopeReports()`
   recurses, because erasure reach does: a depth-1 report would hide a nested pool's whole bill while
   the operator's erasure still reached it. And a descendant's envelope is CLAMPED per dimension to
   its opener's, resolved from the OPENER'S LIVE GROUND. The clamp rides EVERY separate container,
   enveloped or not: a container's ground is a one-way seeded copy, so a declaration that crossed the
   edge and was later struck on the parent stays live in the copy, and a pool nested inside would
   otherwise resolve a ceiling the operator has already retracted. Nothing below the operator widens.
5d. **A per-pool declaration this store can read NOTHING from takes the TIGHTER of the floor and the
   wildcard, per dimension.** `readBudgetPolicy` drops such a subject, which for a quota means
   unmetered; for a CEILING the conservative reading is the tightest one AVAILABLE — the wildcard
   alone would widen an unreadable tightening, and the floor alone would widen wherever the operator's
   wildcard is tighter than the floor. A declaration naming at least one recognized dimension still
   composes with the wildcard dimension by dimension (criterion 16).
5e. **A descendant resolves its own envelope from the ROOT's ground.** Not from the container it sits
   in, whose ground is a seeded copy a later strike never reaches. Otherwise the report and the gate
   would agree on a retracted ceiling, and no one-sided assertion could see it.
6. **The envelope is UNTRUSTED-container-scoped, and metering RIDES DOWN.** It attaches to a separate container opened with
   `trust: "untrusted"` — the quarantine preset and its named equivalents. A trusted or curated
   separate container keeps the primary's ordinary door budgets. Named rather than implied: the
   undelegatable-bill argument is about a child that admits what its parent does not trust. The
   trust is recorded WITH the pool at open time; `quarantinePools` is a bare `Set<Gateway>` and cannot
   answer the question on its own. But a container opened INSIDE a pool is metered whatever it
   declares: its `trust` knob is read from the pool's seeded copy of the container table, where a
   strike on the parent never lands, so letting that knob decide metering would let a metered pool
   host an unmetered child. Trust decides at the top; below an untrusted container, everything is
   metered.
7. **The envelope governs BOTH doors of the pool.** On the primary, `maxPublicRenders` caps the
   anonymous fan only, because the token door is the operator's own. Inside a quarantine every render
   is a stranger's code whichever door asked for it, so the pool's slots cover both.
8. **The slot accounting is the pool's own object.** The primary's `publicRendersInFlight` counter is
   never touched by a pool render, and two pools never share a counter.
9. **Exhaustion is loud and attributable.** The parent gateway answers `envelopeReports()`: one row
   per live pool naming the pool, its resolved envelope, its in-flight count, and its running counts of
   slot refusals, timeouts, and faults. The refusal a caller sees stays leak-free.
10. **Dropping a pool releases its envelope.** The report list is derived from the parent's canonical
    pool registry, so a dropped or detached pool takes its accounting with it, mid-render or not.

## 24.5d What this does NOT claim

**Slots are not cores.** The envelope bounds slot-holding, wall clock, and per-worker memory. It does
not schedule CPU. A pool allowed many slots by its own operator can still burn many cores; the cap is
what makes that the operator's stated decision rather than a stranger's. The primary's doors are
protected because the pool's concurrency is bounded and its accounting is separate — not because any
thread is prioritized. Criterion 2 therefore saturates with bundles that HOLD their slot without
burning CPU, so it measures the property this section actually claims.

**The report is in-process.** `envelopeReports()` is a Gateway method. Putting it on the admin door or
the CLI is a disclosure decision on a capability boundary and is not taken here; it is named as the
obvious follow-on.

**A drop does not kill an in-flight render.** `drop()` unregisters the pool, so its row leaves the
report at once, while a render already in the worker runs to the pool's own clock and then folds into
a refusal. The last window of a dropped pool's bill is therefore unreported. The counter object is the
pool's own, so nothing leaks into a pool opened afterwards — which is what criterion 12 asserts.

## 24.5e Acceptance criteria

Every criterion names its verification.

1. A saturated quarantine pool does NOT cost the primary a render slot: with every pool slot occupied
   by a bundle that holds it to the clock, a concurrent PUBLIC render on the primary answers 200 and
   the primary's own in-flight counter never rose above its own renders. Verified in
   `test/gateway/quarantine-envelope-isolation.test.ts`.
2. A saturated quarantine pool does NOT degrade the primary's doors. Measure an AWAITED primary
   public render plus a door read with the pool idle (baseline), then the same pair while every pool
   slot is held by a bundle parked until its 4000ms clock fires. The awaited render is the load-bearing
   half: it yields to the event loop and spawns its own worker, so a blocked loop shows. Assert the under-load read completes and its latency
   stays within `max(12 x baseline, 750ms)` — an order-of-magnitude bound, generous by design, and far
   under the pool's own clock, so the failure it catches is "the primary blocked until the
   quarantine's timeout fired". The saturating bundles hold their slot without burning CPU, because
   24.5d does not claim CPU isolation. Verified in
   `test/gateway/quarantine-envelope-isolation.test.ts`.
3. The pool's slot cap is the operator's DECLARATION, at BOTH levels: with `maxConcurrentRenders: 1`
   declared at `loam:envelope` on the parent, `envelopeReports()` resolves 1 from the deltas AND the
   second concurrent pool render is refused while the first is in flight. Verified in
   `test/gateway/quarantine-envelope.test.ts`.
4. Object level, same knob: raise the declaration to 3 and the same three concurrent renders all
   answer 200. The knob is live — no restart, no re-open. Verified in
   `test/gateway/quarantine-envelope.test.ts`.
5. A pool with NO declaration is bounded by the built-in default, not unmetered: the default+1th
   concurrent render is refused. Without this rail the whole feature could be deleted and a
   declaration-only suite stay green. Verified in `test/gateway/quarantine-envelope.test.ts`.
6. A declaration appended INSIDE the pool at `loam:envelope` does not raise the pool's ceiling. The
   pool's ground says 32 slots; the pool still refuses at the parent's number. This is 24.5a's
   undelegatable half, asserted. Verified in `test/gateway/quarantine-envelope.test.ts`.
7. The envelope is PER POOL: two pools open at once, one saturated to its cap, and the other serves
   200 concurrently. Neither borrows the other's slots. Verified in
   `test/gateway/quarantine-envelope-isolation.test.ts`.
8. A completed pool render RELEASES its slot: cap+1 renders run sequentially all answer 200. Verified
   in `test/gateway/quarantine-envelope.test.ts`.
9. The pool's wall clock is the envelope's, not the primary's: with a declaration of
   `renderTimeoutMs: 1500`, a hanging render inside the pool is still running well past the primary's
   500ms default before it refuses. A LOWER bound, so the assertion never races a loaded scheduler.
   Verified in `test/gateway/quarantine-envelope.test.ts`.
10. Exhaustion is attributable: after a slot refusal and a timeout in one pool, the parent's
    `envelopeReports()` names that pool, its resolved envelope, and the counts — and a SECOND live pool
    is reported at zero, so the rail sees mis-attribution as well as absence. An anonymous pool is
    named by a stable synthetic handle, never omitted. Verified in
    `test/gateway/quarantine-envelope.test.ts`.
11. The caller-facing refusal leaks nothing: the busy body names no route, no lens, no entity, no
    bundle. Verified in `test/gateway/quarantine-envelope.test.ts`.
12. Dropping a pool releases its envelope: the row shows an in-flight render while one is running, the
    parent's reports lose the row after `drop()`, and a fresh pool opened afterwards starts at zero on
    every counter. Verified in `test/gateway/quarantine-envelope.test.ts`.
13. A malformed envelope declaration is refused at the APPEND door by name, and a well-formed one is
    accepted. Non-declarations are left alone. Verified in `test/gateway/quarantine-envelope.test.ts`.
14. Only the OPERATOR's declaration binds, asserted as a PAIR so the rail cannot pass with the lawful
    filter deleted: the SAME declaration content signed by the operator moves the ceiling, and signed
    by a granted non-operator author it does not. Verified in
    `test/gateway/quarantine-envelope.test.ts`.
15. An unrecognized dimension is tolerated, not rejected, and leaves the recognized dimensions of the
    same declaration in force. Verified in `test/gateway/quarantine-envelope.test.ts`.
16. Resolution is PER DIMENSION: with a wildcard declaration setting slots and clock, a per-pool
    declaration naming ONLY slots leaves the wildcard's clock in force rather than resetting it to the
    built-in default. Verified in `test/gateway/quarantine-envelope.test.ts`.
17. `maxMemoryMb` REACHES the Worker and is not decorative: a pool whose declared memory ceiling is
    small refuses an allocating bundle, and the SAME bundle succeeds in a pool on the default ceiling.
    Two-sided, so the rail cannot pass by refusing everything. Verified in
    `test/gateway/quarantine-envelope-memory.test.ts`.
18. A separate container opened `trust: "curated"` is NOT enveloped: it does not appear in
    `envelopeReports()` and it is not capped at the quarantine default. The envelope is scoped to the
    child that admits what its parent does not trust. Verified in
    `test/gateway/quarantine-envelope.test.ts`.
19a. A struck declaration stops binding at BOTH levels, and reverts to the next rung of the ladder,
    not to the floor: striking a per-pool declaration leaves the wildcard in force; striking the
    wildcard too lands on the floor. Verified in `test/gateway/quarantine-envelope.test.ts`.
19d. A pool nested under a CURATED container is clamped by the operator's LIVE ground — a declaration
    struck after that container was seeded does not bind inside it — and its report row names the path
    rather than a placeholder. Verified in `test/gateway/quarantine-envelope.test.ts`.
19e. A per-pool declaration naming only an unrecognized dimension takes the tighter of floor and
    wildcard: with a wildcard looser on slots and tighter on the clock, the pool gets the floor's
    slots and the operator's clock. Verified in `test/gateway/quarantine-envelope.test.ts`.
19g. A CURATED container opened inside a pool is metered and reported, and its cap is the pool's.
    Verified in `test/gateway/quarantine-envelope.test.ts`.
19f. Only the OPERATOR's STRIKE retires a declaration: a granted author's negation of the operator's
    per-pool tightening moves nothing, and the operator's then does. The strike is the direction that
    WIDENS, so it earns its own pair. Verified in `test/gateway/quarantine-envelope.test.ts`.
19b. A NESTED pool appears in the report under its path, and its opener cannot hand it more than the
    opener holds. Verified in `test/gateway/quarantine-envelope.test.ts`.
19c. A bundle that returns something other than HTML moves the `malformed` counter. Verified in
    `test/gateway/quarantine-envelope.test.ts`.
19. The primary is unchanged by this work: the §23.9 anonymous render cap, its release, and the full
    door's exemption from it all still hold. Verified by the existing
    `test/gateway/render-cap.test.ts`, run unmodified.

# The tutorial — learn Loam by growing one (§48)

Deployed at <https://bombadil-labs.github.io/loam/tutorial.html> (the site root is the landing
page, `demos/site/`) by `.github/workflows/pages.yml` on every push to main. No signup, no
server, nothing installed: the page boots a real governed store in the visitor's browser and
teaches by doing.

The tutorial is TWO things kept apart on purpose — a player and an arc.

- **`player.mjs`** — the ENGINE, UI-free. Progress is deltas: entering a lesson, banking a step,
  answering a quiz, taking a checkpoint and planting a glossary term all land as signed claims
  in the student's own store under a `tutorial.*` vocabulary, and every reading here recomputes
  from the ground. There is no parallel state machine, so a reload cannot disagree with the
  store. It also owns the CHECKPOINTS (`loam:tutorial-ckpt:<lesson>`, one per lesson boundary,
  superseded in place) and their SWEEP: an erasure destroys every checkpoint that holds the
  erased bytes, names them, and keeps the ones that cannot — a copy holds the bytes, so a right
  to be forgotten that spares the undo button is not one.
- **`lessons.mjs`** — the ARC as data. Each lesson is `{id, role, title, copy, terms, quiz?,
  steps, check}` and each step is `{id, label, have, want, how, run, observe}`: the three-way
  framing (what we have / what we want / how we get there) and TWO machine-checkable
  observables, one over the page and one over the store. A step banks only when both hold, so a
  `run` that quietly stops working is refused by name rather than ticked off.
  **The arc in the tree today is a STUB** (T226): three lessons that exercise every mechanic so
  the player can be proven before the real fifteen land (T227).
- **`app.mjs` / `index.html` / `style.css`** — the theater: zero framework, the store is the
  state and the page is a subscriber. One pending step at a time, a progress rail with revert,
  the quiz card, the glossary pane, the introspection drawer, and the Ground pane — which
  filters the tutorial's own records out by default, behind a visible toggle.
- **`instruments.mjs`** — the panes as tools: the delta classifier (badges, including
  `tutorial`), the Ground renderer and its filter, and the View browser.
- **`packets/`** — the bundled world (the circle, the adversary, the dialect): committed data,
  regenerated byte-identically by `scripts/gen-packets.mjs` (`--check` gates drift in CI). The
  stub arc does not federate; the lessons that do come with T227.

**Two rules the page keeps, both load-bearing.** It never calls `window.confirm`: a native
dialog blocks the page's own script until a human answers, so it is a destructive path no rail
can drive — revert and start-over confirm with controls in the page. And revert RELOADS after
re-seeding the rows, because this module captures the gateway once and the View pane holds a
live subscription; reloading makes "the panes re-render from the restored ground" true by
construction.

**The lesson ROLES are a contract**, not decoration: `test/browser/tutorial.test.ts` freezes at
its landing and finds what it exercises by role. An arc that renames or drops one breaks that
suite by design. What each role must actually DO:

- `opening` — the first lesson; boot has already happened.
- `reveal` — plants at least one glossary term from INSIDE a step, not from the lesson's
  `terms` (which are planted on entry). The where-does-this-live payoff needs the student to
  have done something for it.
- `erasure-finale` — erases a record that landed AFTER at least one checkpoint boundary. One
  blob is then holding those bytes when the sweep runs, and an earlier blob is not: the frozen
  suite asserts both sides. Erasing something the same lesson created leaves the sweep nothing
  to destroy; erasing a lesson-1 record leaves it no bystander to spare. Either turns the frozen
  file red with no bug behind it.

**Four more things the arc owes the player**, each with a rail that fails without it: every
lesson has at least one step whose store predicate is FALSE before it runs (a lesson of pure
look-steps teaches a click and proves nothing); every step carries both observables; at least
one lesson declares a quiz; and STEP IDS ARE DURABLE — a banked step is a claim naming the
step by id, so renaming one in a later version silently un-banks it for every student who
already did it.

Build locally: `node scripts/build-site.mjs` then `node scripts/serve-site.mjs` →
<http://127.0.0.1:4173/>. (`--out <dir>` builds elsewhere; the browser rail uses it so two
suites never share one output directory.)

The rails: `test/site/arc.test.ts` walks the arc headlessly and asserts every step's STORE
observable, the progress claims, the checkpoints and the sweep; `test/browser/tutorial.test.ts`
drives the real page in a real Chrome — stepping, the red probe, revert, resume with every
non-store key deleted, the quiz, the Ground filter, the glossary reveal, the drawer, and the
sweep at the bytes.
